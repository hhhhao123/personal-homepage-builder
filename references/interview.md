# Interview Question Bank

Use only the questions needed. Ask 1-3 at a time, then summarize what changed. Provide broad options and always allow the user to describe something outside the list.

Every run needs a clarification dialogue. If the user starts blank, use the full discovery path. If the user uploads rich materials, use a shorter confirmation path focused on intent, audience, privacy, and what the materials should emphasize.

## Round Selection Rule

Before each question round, choose the next missing decision that most affects the brief:

1. public identity, audience, or memory point
2. must-show content and next action
3. privacy boundary and public-use status
4. page shape and material readiness
5. taste, dislikes, references, and motion
6. implementation constraints

Ask no more than three questions. If a user answer contains several areas at once, summarize and move to the highest-impact missing item instead of restarting the checklist.

## Stage 0: Source Materials

- Are we aiming for a quick first version, a more personalized version, a media-rich version, or a publish/update task?
- Do you already have content to upload or paste? Examples: resume/CV, bio, portfolio list, publications, service description, social profile text, article draft, personal notes, link collection.
- Should I treat the provided material as public-ready content, private reference, or mixed material that needs confirmation?
- What should I prioritize from the material: credibility, life story, projects, services, social presence, creative personality, or career opportunities?

## Minimum Confirmation Round

Use this even when source materials are detailed:

- Public identity: should the site present you mainly as a professional, creator, researcher, student, entrepreneur, artist, or multi-role person?
- Audience: who should feel this site was made for?
- Emphasis: what should the materials highlight most, and what should stay secondary?
- Privacy: is anything in the materials private, outdated, sensitive, or not meant for the public site?
- First impression: what should visitors feel in the first 10 seconds?

## Stage 1: Identity And Audience

- Who should this homepage help most: professors/collaborators, recruiters, clients, fans/readers, peers, students, customers, or friends?
- What are your 2-3 current identities? Examples: researcher, engineer, designer, musician, blogger, founder, student, consultant, teacher, doctor, lawyer, artist, athlete, organizer, parent, maker.
- What should a visitor remember after 30 seconds?
- What should the homepage help you get: collaboration, job opportunities, clients, subscribers, credibility, speaking invitations, community, or personal expression?

## Stage 2: Profile Signals

- Are there personal labels or signals you want to use as clues? Examples: MBTI, zodiac, enneagram, introvert/extrovert, hometown, cultural background, favorite season, favorite music, favorite books/films/games, personal symbols.
- If you mention MBTI, zodiac, or a similar label, which part feels accurate and which part should not be represented?
- Which signals should be visible on the site, and which should only influence the atmosphere?
- Which signal is most important: profession, personality, hobbies, cultural taste, life story, values, or visual taste?

## Stage 3: First Impression

- Which first impression is closest: quiet and trustworthy, sharp and technical, warm and approachable, expressive and creative, premium and refined, experimental and bold?
- What should the site not feel like: corporate landing page, plain resume, academic PDF, influencer page, generic AI template, startup SaaS page, portfolio clone?
- Should the homepage feel more like a studio, notebook, lab, gallery, magazine, archive, console, desk, stage, or calm room?

## Stage 4: Story And Content

- What life/work moments belong on the page?
- What existing content must appear: bio, resume, projects, papers, newsletter, videos, photos, contact, services, testimonials, timeline, social links?
- What content should be visually dominant?
- What can be understated or hidden behind secondary links?

## Stage 5: Contact And Social Links

- Which contact methods should be shown: email, phone, location, booking link, contact form, resume download?
- Which professional links should appear: GitHub, LinkedIn, Google Scholar, ORCID, ResearchGate, Behance, Dribbble, portfolio, company page?
- Which creator/social links should appear: X/Twitter, Instagram, Facebook, YouTube, TikTok, Twitch, Threads, Medium, Substack?
- Which China-focused platforms should appear: Douyin, Xiaohongshu, Bilibili, Weibo, Zhihu, WeChat Official Account, Jike, Douban, WeChat QR code?
- Should links be grouped as Professional, Creator, Social, Contact, or shown as one simple link row?
- Are there links that should influence the site's personality but not be visually prominent?

## Stage 6: Media And References

- Do you have reference homepage screenshots, mood images, photos, work images, videos, music, or covers to upload?
- Should media be central to the first screen, used in a gallery/work section, or only used as subtle atmosphere?
- For video: do you want background video, embedded work videos, external video cards, or simple links?
- For music/audio: should it be a visible player/link, a mood reference only, or an optional play button? Do not assume audible autoplay.
- Do you own or have permission to publish the media publicly?
- If you have video links, do you have preferred cover images, or should the site use platform thumbnails/placeholders?

## Stage 7: Taste Without Jargon

- Choose atmosphere words: night, morning, paper, metal, glass, wood, ocean, city, nature, stage, library, studio, lab, arcade, gallery.
- Choose texture words: clean, grainy, cinematic, editorial, handmade, glossy, raw, soft, dense, spacious.
- Choose motion preference: almost none, subtle, expressive, playful, technical, cinematic.
- Name 1-3 sites, apps, artists, brands, games, books, films, or places you like. Ask what they like about them, not just the name.

## Stage 8: GitHub Pages And Constraints

- Existing project or from scratch?
- Preferred hosting: GitHub Pages/github.io by default, Vercel, Netlify, personal server, unknown.
- If GitHub Pages: does the user already have a GitHub username and `username.github.io` repository?
- Does the user need Chinese, English, bilingual Chinese/English, or another language setup?
- Does the user need a downloadable resume, blog, analytics, contact form, or CMS?
- Is speed more important than maximum personalization?
- Should this first version stay lightweight, or should it spend more effort on custom visuals, media, and polish?
